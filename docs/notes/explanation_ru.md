# Конспект По IPv4 И Подсетям (NetPractice)

## 0) Базовые Понятия

- Бит: минимальная единица, `0` или `1`.
- Байт: 8 бит.
- Октет: один байт в IPv4-адресе. В IPv4 всего 4 октета.
- IPv4-адрес: 32 бита, запись вида `a.b.c.d` (каждый октет от 0 до 255).
- Префикс: запись CIDR `/n`, где `n` — число сетевых бит.
- Маска подсети: 32-битное число, где биты сети = `1`, биты хоста = `0`.
- Сетевая часть: биты, которые определяют подсеть.
- Хостовая часть: биты, которые определяют хост внутри подсети.
- Адрес сети: первый адрес подсети (все биты хоста `0`).
- Broadcast (широковещательный адрес): последний адрес подсети (все биты хоста `1`).
- Доступные адреса хостов: адреса между сетью и broadcast.
- Шлюз по умолчанию (default gateway): адрес роутера для выхода в другие сети.
- Линк: прямое соединение интерфейсов (например, роутер-роутер).
- Подсеть: логический сегмент сети, задается маской/префиксом.
- Диапазон подсети: от адреса сети до broadcast.
- Шаг (block size): через сколько увеличивается начало следующей подсети.

## 1) Значения В Октете И Логика Префикса

### Бинарные Веса В Одном Октете

`128 64 32 16 8 4 2 1`

Пример:

- `224 = 128 + 64 + 32 = 11100000` (3 единицы в начале октета)

### Допустимые Значения Октета Маски

Только такие значения могут встречаться в октете маски:

- `0` (`00000000`) -> 0 единиц
- `128` (`10000000`) -> 1 единица
- `192` (`11000000`) -> 2 единицы
- `224` (`11100000`) -> 3 единицы
- `240` (`11110000`) -> 4 единицы
- `248` (`11111000`) -> 5 единиц
- `252` (`11111100`) -> 6 единиц
- `254` (`11111110`) -> 7 единиц
- `255` (`11111111`) -> 8 единиц

### Как Считать Префикс По Маске

Пример: `255.255.255.224`

- `255` -> 8 бит
- `255` -> 8 бит
- `255` -> 8 бит
- `224` -> 3 бита

Итого: `8 + 8 + 8 + 3 = /27`

### Один И Тот Же Октет В Разных Позициях

- 1-й октет `255` дает `/8`
- 2-й октет `255` дает суммарно `/16`
- 3-й октет `255` дает суммарно `/24`
- 4-й октет `255` дает `/32`

---

## 2) Сколько Бит Уходит На Хосты

Формула:

- `host_bits = 32 - prefix`

Примеры:

- `/24` -> `32 - 24 = 8`
- `/27` -> `32 - 27 = 5`
- `/30` -> `32 - 30 = 2`

---

## 3) Сколько Всего Адресов В Подсети

Формула:

- `total_addresses = 2^(host_bits)`

Примеры:

- `/24`: `2^8 = 256`
- `/27`: `2^5 = 32`
- `/30`: `2^2 = 4`

---

## 4) Сколько Доступных Хостов

Классическая формула:

- `usable_hosts = 2^(host_bits) - 2`

Почему `-2`:

- один адрес — это адрес сети
- один адрес — это broadcast

Примеры:

- `/24`: `256 - 2 = 254`
- `/27`: `32 - 2 = 30`
- `/30`: `4 - 2 = 2`

Особые случаи:

- `/31` обычно применяют для point-to-point линков.
- `/32` — это маршрут/адрес одного хоста.

---

## 5) Как Считать Шаг

Формула:

- `step = 256 - mask_octet`

Берем первый октет маски, который не равен `255`.

Примеры:

- `/27` -> маска `255.255.255.224` -> шаг `256 - 224 = 32`
- `/26` -> маска `255.255.255.192` -> шаг `256 - 192 = 64`
- `/28` -> маска `255.255.255.240` -> шаг `256 - 240 = 16`

---

## 6) Как Найти Диапазоны Подсетей

Алгоритм:

1. Находим интересный октет (первый октет маски, который не `255`).
2. Считаем шаг.
3. Выписываем начала подсетей: `0, step, 2*step, ...`.
4. Смотрим, в какой интервал попадает IP.

Пример: `192.168.1.77/27`

- `/27` -> маска `224`, шаг `32`
- начала: `0, 32, 64, 96, 128, 160, 192, 224`
- `77` попадает в диапазон `[64..95]`

Значит:

- Адрес сети: `192.168.1.64`
- Broadcast: `192.168.1.95`
- Хосты: `192.168.1.65 - 192.168.1.94`

---

## 7) Как Определить, В Какой Сети Находится IP

Два способа:

- Быстрый: через шаг и диапазоны.
- Точный: `network = ip AND mask`.

Пример:

- IP: `10.20.30.200`
- Маска: `255.255.255.192` (`/26`)
- Шаг в 4-м октете: `64`
- Диапазоны: `0-63, 64-127, 128-191, 192-255`
- `200` в диапазоне `192-255`

Итог:

- Сеть: `10.20.30.192/26`

---

## 8) Адрес Сети И Broadcast

Правила:

- Адрес сети: все биты хоста `0`
- Broadcast: все биты хоста `1`

Пример: `172.16.5.130/26`

- `/26` -> шаг `64`
- диапазоны: `0-63, 64-127, 128-191, 192-255`
- `130` попадает в `128-191`

Значит:

- Сеть: `172.16.5.128`
- Broadcast: `172.16.5.191`
- Хосты: `172.16.5.129 - 172.16.5.190`

## Дополнительно: Быстрый Чеклист Для NetPractice

1. Переведи префикс в маску (или наоборот).
2. Найди интересный октет и шаг.
3. Определи адрес сети, broadcast и диапазон хостов.
4. Проверь, что IP хоста не равен сети или broadcast.
5. Проверь, что хост и gateway в одной подсети.
6. Проверь маршруты на роутерах (default и статические).
7. Проверь обратный путь (reverse route), это частая ошибка.

## 9) Основы IP (3 Уровень)

IP отвечает за логическую адресацию и маршрутизацию между сетями.

Что делает IP:

- добавляет адрес источника и назначения
- позволяет роутерам пересылать пакеты между подсетями
- работает по принципу best effort (без гарантии доставки)

Важные поля IPv4-заголовка (упрощенно):

- Source IP
- Destination IP
- TTL (уменьшается на каждом роутере)
- Protocol (например TCP = 6, UDP = 17)

Про TTL:

- каждый роутер уменьшает TTL на 1
- если TTL стал 0, пакет отбрасывается
- это защищает от бесконечных петель маршрутизации

---

## 10) Основы TCP (4 Уровень)

TCP — это протокол транспортного уровня с установкой соединения.

Что дает TCP:

- надежную доставку (повторная отправка при потере)
- правильный порядок сегментов (sequence numbers)
- проверку ошибок (checksum)
- контроль потока и перегрузки

Основные поля TCP:

- Source port
- Destination port
- Sequence number
- Acknowledgment number
- Флаги (SYN, ACK, FIN, RST)

### 3-way handshake

1. Client -> Server: SYN
2. Server -> Client: SYN-ACK
3. Client -> Server: ACK

После этого начинается обмен данными.

### Закрытие соединения (упрощенно)

- обмен FIN/ACK (или RST при резком закрытии)

---

## 11) Разница IP И TCP

- IP определяет, куда отправить пакет (адресация и путь).
- TCP определяет, как надежно доставить данные между двумя приложениями.

Коротко:

- IP = путь между хостами
- TCP = надежный диалог поверх этого пути

---

## 12) Порты И Сервисы

- Порт определяет сервис на хосте.
- Пара IP + порт определяет конечную точку (например `192.168.1.10:80`).

Примеры:

- HTTP: TCP/80
- HTTPS: TCP/443
- SSH: TCP/22

В контексте NetPractice:

- маршрутизация доставляет пакет к нужному IP
- TCP/порт доставляет пакет в нужное приложение на этом IP
